01 · 它是什麼

一句話：Cursor 官方 repo 裡的工作流外掛

核心是入口 /poteto-mode：依任務挑一本 playbook，再按步驟叫用其他技能，最後用可驗證的證據收尾。

作者

Lauren Tan（poteto），Cursor 工程師。

目標

寫少一點、寫對一點，不追求程式碼行數。

授權

來源：github.com/cursor/plugins/tree/main/pstack（版本 0.15.48，最後 commit 2026-11-24）

03 · 安裝

兩種環境，兩組指令

Cursor

/add-plugin pstack

Claude Code

/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins

在 Claude Code，指令要加前綴：/poteto-mode 變成 /pstack:poteto-mode。

04 · Claude Code 版的注意事項

更新、功能、副本，各有一個坑

  • 預設不自動更新 — 第三方 marketplace 預設關閉。要開：/plugin → marketplaces → cursor-plugins → enable auto-update；手動更新用 claude plugin update pstack@cursor-plugins
  • Cursor 專屬功能會被跳過 — 例如 Bugbot、Automations，並印一行說明
  • 安裝的是生成副本 — 來自 harness/pstack/；改完 pstack 要跑 node scripts/generate-pstack-harness-trees.mjs 並 commit，CI 會檢查是否過期

06 · README 的預設模型

不設定也能跑，預設長這樣

工作預設
寫程式、修 bug、perf、hillclimb、文字與判斷Opus 5.5 xhigh
Fable 5.2只在你點名，或同一份 brief 兩次 Opus 都失敗時才用
評審小組（panel）Fable 5.2 ／ Opus 5.5 ／ Gemini 4 Neon

任何角色都不會超過 xhigh；/setup-pstack 可以改掉以上全部。

07 · 提示詞怎麼寫

目標、完成判準、證據形式

/poteto-mode 這個 PR 有個細微 bug：閒置時捲動每 750ms 會漂移。
先 repro，再修，並驗證。
  • 目標 — 哪裡壞了／你要什麼
  • 完成判準 — 必須能 pass／fail
  • 證據形式 — 要看到什麼輸出

10 · 成本提醒

嚴謹要花錢，花在三個地方

×N

panel 長度

清單每個 entry 就是一個 subagent。

×N

swarm 切片

切片數就是倍數。

⏱

長跑

autonomous run、autopilot 這類是最貴的部分。

README 建議：小而明顯的改動不要套 poteto-mode；把嚴謹留給「錯了很貴」的地方（設計、併發、資料、對外 API）。

11 · 風險與限制

安裝前請知道這四件事

項目我看到的
安全公告repo 的 security advisories 是空的；只代表沒有公開公告，不代表沒有問題。
腳本有 worktree-audit.sh、log.sh 與兩個 package.json，我沒有逐行讀，建議安裝前自己看。
效果「每天用、做出高品質程式」是作者自己的說法；找不到獨立實測比較。
Claude Code 版部分功能被跳過，Cursor 專屬功能不能用。

補充：搜尋到的 Cursor CVE（如 CVE-2025-54135、CVE-2025-54136）是 Cursor 本身的問題，與 pstack 無直接關係。

12 · 適不適合你

看你的任務，不是看工具

適合

有驗收條件、要留證據

先定 done 判準、先 repro、要真實輸出當證據。這套想法即使不裝外掛也值得借來用。

不適合

小改動

套整套流程只會增加成本。

安裝前：先看過 scripts，並決定要不要開自動更新。
