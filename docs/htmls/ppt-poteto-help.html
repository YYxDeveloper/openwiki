01 · 它是什麼

一句話：幫你找對技能、設定、劇本、原則

原文描述：帶你走過 pstack 設定、/poteto-mode，以及替任務挑技能、playbook 或原則。

怎麼啟動只有你輸入 /poteto-help 才會跑（disable-model-invocation）
它給你答案 + 一段可送出的 prompt + 來源檔連結
它不給不替你開始做事

02 · 比喻

像大樓一樓的「服務台」

大樓poteto-help
服務台/poteto-help
你問「某某部門在哪」你問「哪個技能可以審 PR」
櫃台給你的路線單一段可以直接送出的 prompt
各部門辦公室各個 skill、playbook、指南頁
服務台不替你辦事help 只指路，由你決定要不要送出

03 · 最重要的規則

「問怎麼做」和「叫它去做」是兩回事

help 問題

問「怎麼做」

例：which skill should i use to review this branch？→ 只回答、給 prompt，不開工。

工作請求

叫它「去做」

例：use pstack to fix this bug。→ 不算 help 問題，改讀 poteto-mode，在它底下做事，並提一次 Custom Mode 可以讓它保持開啟。

原因：你問的是怎麼做，而 pstack 一次執行會花真實 token，所以由你自己決定何時送出。

05 · 它會先檢查你的狀態

只有「會改變答案」時才提醒你

檢查到代表它會提
沒有 pstack-models.mdc還沒跑過 /setup-pstack，每個角色用預設模型/setup-pstack
專案沒有 verify-* 技能agent 沒有腳本化方式驅動 app問「證明改動有效」時提 /create-verification-skill
專案沒有形式驗證技能測試碰不到的性質沒人檢查問 race、不變式時提 /create-formal-verification-skill

已有形式驗證，且它涵蓋的程式碼在「最後同步」的 commit 之後改過 → 問題碰到那段程式碼時提 /maintain-formal-verification-skill。

06 · 缺模型規則時

每個對話最多問你一次

在這些情況才會問：你是新手、問題和設定或成本有關、答案取決於跑哪些模型。

Now

現在就設

給你 /setup-pstack 去輸入，並一併回答你的問題。

Later

之後再說

先回答問題，加一行：在你跑 /setup-pstack 之前，每個角色都用預設模型。

需求也不清楚時，兩個問題會一起問。

07 · Get set up

三步開始

1

安裝

在對話中輸入 /add-plugin pstack，或從側邊欄的 Customize 安裝。

2

/setup-pstack

選推理預算、為每個角色對應模型，寫成規則，只對新對話生效。

3

開始真任務

/poteto-mode + 目標 + 能 pass／fail 的檢查。

  • 安裝本身不會改變任何事，直到你叫用某個技能
  • 只有 /setup-pstack 會從你的話語載入，其他要你輸入，或由 /poteto-mode 叫用

08 · 在別的環境用

Claude Code 與其他工具

# Claude Code
/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins
  • 指令要加 pstack: 前綴，例如 /pstack:poteto-mode
  • 需要 Cursor 專屬功能的步驟（Bugbot、Automations）會被跳過並印一行說明
  • 其他工具可讀技能（Agent Skills 格式），但 /poteto-mode、/how、/teach 這類技能會產生 Cursor subagent，Custom Modes 與 /loop 也是 Cursor 功能，這些部分可能無法運作

09 · 擔心成本？

token 花在哪、怎麼少花

pstack 的額外花費主要來自 subagent 和評審小組。

1

降預算或換便宜模型

重跑 /setup-pstack，選較小預算或較便宜的模型。

2

用 auto／inherit-parent

角色設成這兩個，就用對話本身的模型；對話跑在 Auto 或較便宜模型時能省 token。

3

縮短 panel 清單

清單每一項就是一個 subagent。

4

只在需要時用 poteto-mode

把它留給需要嚴謹的工作。

10 · Start a task

poteto-mode 會一直開著嗎？看你怎麼啟動

怎麼啟動效果
在 /poteto-mode 上按 Enter只附在那一則訊息，對話往下走就淡掉
Option+Enter（Mac）／Alt+Enter（Windows），或技能項目的 Use as Mode變成 Custom Mode，每一輪都留在 context，直到你退出；休閒對話不會被它影響
  • Custom Modes 在 Agents Window 與 CLI 可用；其他地方，每個新任務都重新輸入 /poteto-mode
  • 對話中途說「new task」，mode 會配對一個新的 playbook
  • 好 prompt 寫目標與完成判準，不要列技能，手排順序容易漏掉 playbook 原本會保留的步驟

12 · 容易混淆的幾組

兩兩比較，一次分清楚

比較差別
/how vs /why vs /teachhow 講程式做什麼；why 講原因；teach 跑其中一個或兩個，再用白話講結果
/arena vs /swarmarena：同一份 brief 多人做，合併最好的；swarm：切成片或賽跑，回一份報告
/interrogate vs /blast-radiusinterrogate 審 diff；blast-radius 找 diff 之外的破壞，並證明一個讓它安全的事實
/recall vs /ketchuprecall 重建近期多個對話的脈絡；ketchup 只講這個對話自你上一則訊息以來的變化
/figure-it-out vs Autonomous run前者設計一次嚴謹的執行；後者把一個任務推進到完成條件

13 · 不是 pstack 的東西

別在 pstack 找這些

  • /deslop、control-cli、control-ui → 來自 cursor-team-kit 外掛
  • /loop、/create-skill → Cursor 內建
  • /orchestrate → pstack 沒有；斜線選單若出現，是別的外掛提供
  • 沒有規劃（planning）技能 → 可搭配 Cursor 的 Plan Mode；跨階段或 stacked PR，請 /poteto-mode 做計畫，會走 Multi-phase plan playbook（只寫計畫，不實作）
  • 設計問題 → 用 Prototype playbook 或 /architect 先用程式碼定案

14 · 用一句話點名 playbook

16 · Fix a run that went wrong

症狀 → 處方

症狀處方
mode 幾輪後不再作用當初用 Enter 啟動。改用 Custom Mode，或每個任務都重新 /poteto-mode
問題被當成上個任務的下一步說「new task」，或說這輪不需要 mode
新的模型選擇沒生效/setup-pstack 的規則只套用到新對話，開新對話
平行 agent 互相覆蓋每個 agent 一個 worktree，或用 cloud agent（各自一台機器）
過夜跑了但沒完成任何事/loop 需要能 pass／fail 的檢查，不是時間長度
回覆以綠燈 build 宣稱成功要真實的指令、流程、儲存值或 profile（prove it works）

把它變成你的

18 · 它怎麼回覆

先給答案，再給一個 prompt，再給連結

  • 答案放最前面
  • 最多一個範例 prompt — 放在程式碼區塊，有合適的就改自 recipes
  • 附該檔案的連結 — 給公開版本：github.com/cursor/plugins/blob/main/pstack/ + 路徑，因為已安裝的外掛你可能打不開
  • 保持簡短 — 除非你要的是整張地圖
  • 引用前先讀過那個檔案 — 和這張地圖衝突時，以該檔案為準

20 · 解答

對一下答案

  • Q1 → 不算。這是工作請求；改讀 poteto-mode，在它底下做事，並提一次 Custom Mode。
  • Q2 → 規則只套用到新對話，要開新的對話。
  • Q3 → /blast-radius。/interrogate 審的是 diff 本身。
  • Q4 → 例如：降預算／換便宜模型、角色設 auto／inherit-parent、縮短 panel 清單、只在需要時用 /poteto-mode（任選兩個）。
