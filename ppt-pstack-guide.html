00 · 指南的核心

一個習慣：停止微管理

你描述想要什麼、以及怎麼知道完成了。/poteto-mode 會挑劇本（playbook）、在每個步驟叫用其他技能，最後把證據給你看。

你給目標 + 可檢查的完成條件
它做配劇本 → 照步驟叫技能 → 執行
你收證據（真實輸出、結果），不是「做好了」

原文：docs/guide/README.md

01 · 只記一件事

用自己的話：目標 + 怎麼檢查

/poteto-mode the export writes duplicate rows when a retry lands mid-run.
repro first, then fix and verify.
  • 不用指定劇本 — 也不用列技能清單
  • 「repro first」加上可檢查的結果 — 就是 poteto-mode 需要的全部路由訊號
  • 它會配到 Bug fix 劇本、把步驟抄進 todo，並在每一步叫對的技能

08 · 卡住時

問 /poteto-help

/poteto-help which skill should i use to review this branch?
  • 它會回答 — 並給你一段可以送出的 prompt，附上答案來源的技能或指南頁連結
  • 它不會開始做事 — pstack 的一次執行會花真實 token，所以由你準備好時再送
  • 只在你輸入時才執行

→ skills/poteto-help/SKILL.md

09 · 課堂練習

把模糊的話，改成「目標 + 怎麼檢查」

模糊說法你要補什麼
修一下匯出哪裡壞？怎樣算修好？要看到什麼輸出？
讓它快一點快到多少？用什麼指標量？量給我看。
重構這個模組行為要不變；用什麼檢查證明沒變？

提示：指南範例是「重現 → 修 → 驗證」，記得寫上 repro first 與可檢查的結果。
