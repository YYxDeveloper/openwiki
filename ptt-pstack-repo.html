[心得] pstack：cursor/plugins 裡的 pstack 外掛，實際裝什麼、怎麼用

來源 github.com/cursor/plugins/tree/main/pstack（MIT，版本 0.15.48，最後 commit 2026-11-24）

前言：這篇只根據 repo 的 README、plugin.json、目錄結構與 commit 紀錄寫成，我沒有實際跑過它。文中「作者說」的部分都是作者自己的說法，請用同樣方式看待。

📌 一句話總結

pstack 是 Cursor 官方 plugin repo 裡的一組 agent 工作流技能，作者是 Cursor 工程師 Lauren Tan（poteto）。它的核心是一個入口 /poteto-mode，依任務挑一本 playbook，再按步驟叫用其他技能。目標是「寫少一點、寫對一點」，用可驗證的證據收尾。

🧭 它到底是什麼

  • 入口：/poteto-mode。讀你的需求，配對 22 本 playbook 之一，把步驟開進 todo。
  • Playbook：22 本，例如 bug fix、feature、perf、refactoring、babysit、shipping、autonomous run。
  • Skill：目錄 skills/ 底下共 59 個子目錄（含 setup-pstack、how、why、arena、swarm、interrogate、tdd 等）。
  • 原則：24 條 principle-*，對話中講出名字，agent 就會依該原則轉向。
  • Subagent：agents/ 底下有 poteto-agent.md 與 comment-sicko.md。

注意：舊的 PTT 文章寫「58 個技能」。以這次 main 的目錄為準是 59 個子目錄，數字會隨 commit 變動。

🛠️ 安裝

Cursor：

/add-plugin pstack

Claude Code：

/plugin marketplace add cursor/plugins
/plugin install pstack@cursor-plugins
  • Claude Code 預設不自動更新第三方 marketplace。要開自動更新，請到 /plugin → marketplaces → cursor-plugins 勾選 enable auto-update；手動更新用 claude plugin update pstack@cursor-plugins。
  • 在 Claude Code 裡指令會加前綴，/poteto-mode 變成 /pstack:poteto-mode。
  • 只能在 Cursor 用的功能（bugbot、automations）在 Claude Code 會被跳過，並印一行說明。
  • Claude Code 安裝的是 harness/pstack/ 下的生成副本，改完 pstack 要跑 node scripts/generate-pstack-harness-trees.mjs 並 commit，CI 會檢查副本是否過期。

🚀 兩步開始

  1. 跑 /setup-pstack，選推理預算（large／medium／small），並選每個角色用哪個模型。
  2. 任務開始時用 /poteto-mode，把需求和驗收條件一起丟進去。

README 的預設值：寫程式、修 bug、perf、hillclimb、文字與判斷類任務都走 Opus 5.5 xhigh；Fable 5.2 只在你點名，或同一 brief 的兩次 Opus 都失敗時才用。預設 panel 是 Fable 5.2 ／ Opus 5.5 ／ Gemini 4 Neon。

🧪 作者建議的提示詞寫法

/poteto-mode 這個 PR 有個細微 bug：閒置時捲動每 750ms 會漂移。
先 repro，再修，並驗證。

作者給的提示詞都包含三件事：目標、完成判準（能 pass／fail）、證據形式。

⚖️ 作者的成本提醒

  • panel 清單每個 entry 就是一個 subagent，數量直接放大成本。
  • swarm 的切片數、以及 autonomous run、autopilot 這類長跑，是最貴的部分。
  • README 建議：小而明顯的改動不要套 poteto-mode；把嚴謹留給「錯了很貴」的地方（設計、併發、資料、對外 API）。

🔍 我看到的風險與限制

  • 沒有公開的安全公告：repo 的 security advisories 清單是空的。這只代表沒有公開公告，不代表沒有問題。
  • 有 shell 腳本與 npm 設定：skills/poteto-mode/scripts/worktree-audit.sh、skills/show-me-your-work/scripts/log.sh，以及 statechart、poteto-mode 的 package.json。我沒有逐行讀，安裝前建議自己看一遍。
  • 效果沒有獨立評測：作者說「每天用、在 Cursor 上用來做出高品質程式」，這是作者自己的說法。目前網路上找不到獨立的實測比較。
  • Claude Code 版行為可能不同：有些功能被跳過，且 Cursor 專屬功能不能用。
  • Cursor 本身的安全背景：搜尋到的公開資料顯示 Cursor 過去有 MCP、prompt injection、extension 的 CVE（例如 CVE-2025-54135、CVE-2025-54136），但這些跟 pstack 沒有直接關係，是 Cursor 本身的問題。

🗣️ 我的結論

如果你常做「有驗收條件、要留證據」的工作，pstack 的想法（先定 done 判準、先 repro、要真實輸出當證據）值得借來用，即使不裝這個外掛也一樣。如果你的任務是小改動，套整套流程只會增加成本。安裝前請先看過 scripts，並決定要不要開自動更新。
